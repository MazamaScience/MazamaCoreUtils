# Architecture Notes — MazamaCoreUtils

This document is maintained as a reference for human maintainers and as context
for AI assistants working on this codebase. Source code, inline comments, and
human-reviewed release notes remain authoritative.

---

## FOR HUMANS

### Purpose and Scope

MazamaCoreUtils is an R package of small, dependable utilities for production
R code: logging, error handling, cache management, API-key handling, explicit-
timezone date-time handling, location validation and IDs, HTML scraping, and
source-code linting. It exists so that MazamaScience packages and operational
pipelines share one standardized set of building blocks.

It does **not** provide spatial data or geoprocessing (that lives in
MazamaSpatialUtils), general data wrangling, or domain-specific analysis.

### Relationship to Other Systems

- **Depends on:** **logger** (logging backend), **lubridate** (date-time
  parsing), **geohashTools** (location IDs), **rvest**/**xml2** (HTML
  scraping), **stringr**, **dplyr**, **purrr**, **tibble**, **magrittr**,
  **rlang**, and **devtools** (used by the `check_*()` wrappers).
- **Depended on by:** other MazamaScience R packages and operational systems,
  which call these utilities directly. Treat every exported function name,
  argument, default and return type as a public contract.
- **Persisted formats:** `initializeLogging()` writes fixed-name log files
  (`TRACE.log`, `DEBUG.log`, `INFO.log`, `WARN.log`, `ERROR.log`, optionally
  with a prefix) and archives old ones with a UTC timestamp suffix; location
  IDs are geohash strings. Downstream tooling may depend on both.

### Distribution and Installation

- Released on CRAN (`install.packages("MazamaCoreUtils")`) and GitHub
  (`devtools::install_github("mazamascience/MazamaCoreUtils")`).
- The version is defined in `DESCRIPTION` (`Version:`); release tags match the
  version (e.g. `0.6.2`). Release notes go at the top of `NEWS.md`.
- `.Rbuildignore` keeps `.claude/`, `docs/`, `_pkgdown.yml`, `local_test/`,
  RStudio files and other non-package files out of the built package.
- Releases are prepared with `/pre-publish`; pushing and CRAN submission are
  done manually by the maintainer.

## FOR AI

The sections below provide architectural context to help AI assistants understand
how this codebase is structured, why it is designed the way it is, and how
changes in one area may affect others.

### Core Data Conventions

Load-bearing assumptions that downstream packages rely on:

- **Explicit timezones.** Every date-time function takes a `timezone`
  (Olson name, validated with `OlsonNames()`) and returns `POSIXct` in that
  timezone. Nothing depends on the system clock or local timezone
  (`Sys.time()` and `Sys.Date()` are flagged by `timezoneLintRules`).
- **Compact datetimes.** `parseDatetime()` accepts `Y`, `Ym`, `Ymd`, `YmdH`,
  `YmdHM`, `YmdHMS` in numeric or character form (also Julian day-of-year),
  and mixed vectors.
- **Locations** are decimal degrees, longitude in [-180, 180], latitude in
  [-90, 90]. Invalid locations map to `invalidID` (default `NA`).
- **NULL semantics.** Required arguments default to `NULL` and are guarded by
  `stopIfNull()`; optional ones are normalized with `setIfNull()`.
- **Log levels** are the exported integer constants `FATAL`, `ERROR`, `WARN`,
  `INFO`, `DEBUG`, `TRACE` (named integers), kept for backward compatibility.

### Dependency / Call Graph

```
stopIfNull, setIfNull     <- foundation; used by nearly every exported function
utils-logging (logger.*)  <- initializeLogging, stopOnError (only if initialized)
stopOnError               <- initializeLogging, loadDataFile
parseDatetime             <- dateRange, timeRange, dateSequence, timeStamp
                             (which wrap lubridate)
timeRange                 <- dateRange
createLocationMask        <- createLocationID
html_getLinks             <- html_getLinkNames, html_getLinkUrls
html_getTables            <- html_getTable
```

`validateLonLat()` / `validateLonsLats()` are standalone; `createLocationMask()`
and `createLocationID()` do their own validation and do not call them.

`stopIfNull()`, `setIfNull()` and `stopOnError()` are shared foundations:
changing their behavior affects almost the whole package and downstream
packages. Verify the exact call edges with `grep` before relying on this diagram.

### Key Design Decisions

1. **Timezones are never implicit.** The package exists to remove a common
   source of error in environmental time series. Do not add timezone defaults
   or "helpful" fallbacks to local time.
2. **Legacy logging API over a modern backend.** In 0.6.0 futile.logger was
   replaced by **logger**, but `logger.*()` names, printf-style formatting and
   level constants were kept so downstream code did not change. All output goes
   through the fixed namespace `"MazamaCoreUtils"`.
3. **Fixed logger indices.** `logger.setup()` uses index 1 for the console
   (FATAL only by default) and indices 2-6 for TRACE/DEBUG/INFO/WARN/ERROR
   files. Index 1 is never deleted, because **logger** errors on an empty
   namespace; setup is made idempotent by resetting indices 2..n.
4. **Initialization flag via `options()`.** `logger.isInitialized()` reads
   `options("MazamaCoreUtils.logger.initialized")`, so `stopOnError()` logs only
   when logging has been set up and stays usable without it.
5. **`setIfNull()` never coerces user-supplied values** unless
   `enforcedType` is given (fixed in 0.6.1).
6. **`createLocationID()` is geohash-only.** The `algorithm` argument is
   retained (0.6.2) for signature compatibility, but `"digest"` is deprecated
   and errors.
7. **Deliberate `try()` + `stopOnError()` idiom** for fragile operations, giving
   consistent, truncated, logged messages instead of raw R errors.
8. **API keys are session state** in a package-private environment
   (`MazamaCoreUtilsEnv`); they are never written to disk.

### Public API Contract

Anything exported in `NAMESPACE` is public. These changes warrant a version
bump and a `NEWS.md` entry (and usually deprecation first):

- Renaming, removing, or reordering arguments of an exported function
- Changing argument defaults or return types/classes
- Changing log file names, log line layout, or log level constants
- Changing the output format of `showAPIKeys()` (keys are masked by default;
  `mask = FALSE` prints them in full)
- Changing datetime format acceptance in `parseDatetime()` or end-of-period
  behavior in `dateRange()` / `timeRange()`
- Changing the geohash algorithm or precision default in `createLocationID()`
- Changing the entries in `timezoneLintRules`

### Validation and Error Handling

| Condition | Behavior | Where |
|-----------|----------|-------|
| Required argument is `NULL` | `stop()` naming the argument | `stopIfNull()` |
| Wrong type or length of argument | `stop()` with `'arg' must be ...` | each function |
| Timezone not in `OlsonNames()` | `stop()` | date/time functions |
| Lon/lat out of range or non-numeric | `stop()` | `validateLonLat()`, `validateLonsLats()` |
| Invalid lon/lat values (mask / ID) | `FALSE` / `invalidID`, no error | `createLocationMask()`, `createLocationID()` |
| Unparseable datetimes | Error if `expectAll = TRUE`; otherwise `NA` | `parseDatetime()` |
| `try-error` result | Cleaned, truncated, logged (if initialized) error | `stopOnError()` |
| Logging function called before setup | `stop()` | `.stopIfNotInitialized()` in `utils-logging.R` |
| Both `dataDir` and `dataUrl` fail | `stop()` | `loadDataFile()` |

### Build and Distribution

Standard R package build (`devtools::document()`, `devtools::check()`,
`R CMD build`). Do not hand-edit `NAMESPACE`, `man/`, or `docs/`. The
`check_*()` functions wrap `devtools::check()` at several levels of
thoroughness. Only `DESCRIPTION` holds the version.

### Testing

- testthat (>= 3.1.7); tests in `tests/testthat/test-<topic>.R`, runner
  `tests/testthat.R`; run with `devtools::test()`.
- Tests cover API keys, cache management, location utilities, date/time
  functions (including shared timezone validation), error handling, logging,
  `loadDataFile()`, the HTML helpers (local files only), the linting functions,
  `setIfNull()` and `stopIfNull()`. Not currently tested: `check_*()`. Tests make no
  network requests: `loadDataFile()` uses local `file://` URLs and the HTML
  helpers use local files. Ad-hoc scripts are in `local_test/`.
- CI: none, by design. This is a single-developer project and checks are run
  locally before pushing (`check_fast()`, `check_slower()`, `/wrap-up`,
  `/pre-publish`). Windows is checked before each release with
  `devtools::check_win_devel()`, which uploads to CRAN's win-builder and emails
  the results; `/pre-publish` lists this as a developer step. Revisit if
  outside contributors or platform-specific dependencies are added.

### Documentation

- roxygen2 (markdown enabled); regenerate with `devtools::document()`.
- pkgdown site in `docs/`, configured by `_pkgdown.yml`; new exports must be
  added to its `reference:` sections.
- Vignettes in `vignettes/` (four articles); `README.md` is hand-written.
- `NEWS.md` is the authoritative changelog.

### Known Limitations and Future Work

- Untested areas listed under Testing; `local_test/` scripts are not run
  automatically.
- `_pkgdown.yml` pins old pandoc/pkgdown versions.
- `DESCRIPTION` lists `devtools` in `Imports` (needed only by `check_*()`);
  moving it to `Suggests` would be a possible, but behavior-affecting, change.
- Do not "fix" these as part of unrelated work without the maintainer's approval.
